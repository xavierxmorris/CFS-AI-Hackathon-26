## Recommended Phases (Incremental, Not a Rewrite)

### Phase 1 — Fix the Security Issue (Do This Now)

**SQL Injection in `CustomerRepository.FindByEmail()`**

```csharp
// ❌ CURRENT — string concatenation in SQL
"SELECT ... FROM Customers WHERE Email = '" + email + "'"

// ✅ FIX — parameterized query
"SELECT ... FROM Customers WHERE Email = @email"
cmd.Parameters.AddWithValue("@email", email);
```

**Why first:** This is a live vulnerability. Everything else can wait; this cannot.

### Phase 2 — Extract Interfaces (Enable Testing)

Before changing any behavior, make the code testable:

```csharp
// Extract from CustomerRepository
public interface ICustomerRepository
{
    Customer GetCustomerById(int customerId);
    void AddLoyaltyPoints(int customerId, int points);
    Customer FindByEmail(string email);
}

// Extract from PaymentService
public interface IPaymentService
{
    bool ChargeCustomer(string email, decimal amount, string token);
    bool RefundCharge(string transactionId, decimal amount);
}
```

Then modify `OrderProcessor` to accept them via constructor injection:

```csharp
public class OrderProcessor
{
    private readonly ICustomerRepository _customerRepo;
    private readonly IPaymentService _paymentService;
    private readonly string _connectionString;

    public OrderProcessor(
        ICustomerRepository customerRepo,
        IPaymentService paymentService,
        string connectionString)
    {
        _customerRepo = customerRepo;
        _paymentService = paymentService;
        _connectionString = connectionString;
    }
}
```

**Why second:** This changes no behavior but lets you write tests for Phase 3+.

### Phase 3 — Add Tests for Current Behavior

Write tests *before* refactoring further. Cover these critical paths:

| Test | What It Verifies |
|------|-----------------|
| Inactive customer → rejected | Status check works |
| Insufficient stock → rejected | Quantity validation works |
| Loyalty discount applied when > 500 points | Discount capped at $50 |
| Loyalty discount NOT applied when ≤ 500 | Threshold is correct |
| Payment failure → no order created | Transaction rollback works |
| Email failure → order still succeeds | Email is non-critical |
| Tax calculation per state | CA, NY, TX, default rates |

**Why third:** These tests become your safety net for all future changes.

---

### Phase 4 — Separate Concerns from OrderProcessor

Extract the inline responsibilities into dedicated classes:

| Extract | From | Into |
|---------|------|------|
| Product lookup + stock check | OrderProcessor (inline SQL) | `IProductRepository` |
| Tax calculation | OrderProcessor.GetTaxRate() | `ITaxCalculator` |
| Loyalty discount logic | OrderProcessor (inline) | `IDiscountService` |
| Email sending | OrderProcessor.SendConfirmationEmail() | `INotificationService` |
| Error logging | EventLog.WriteEntry() calls | `ILogger` (Microsoft.Extensions.Logging) |

After extraction, `OrderProcessor.ProcessOrder()` becomes a clean orchestrator:

```csharp
public int ProcessOrder(int customerId, string productCode, int quantity, string token)
{
    var customer = _customerRepo.GetCustomerById(customerId);
    // validate...
    var product = _productRepo.GetProduct(productCode);
    // check stock...
    var total = _taxCalculator.CalculateTotal(product.Price, quantity, customer.State);
    total = _discountService.ApplyDiscount(total, customer.LoyaltyPoints);
    // charge, save, notify...
}
```

### Phase 5 — Modernize Infrastructure (When Ready)

| Replace | With | Benefit |
|---------|------|---------|
| .NET Framework 4.5 | .NET 8+ | Cross-platform, performance, LTS support |
| ADO.NET inline SQL | Entity Framework Core or Dapper | Less boilerplate, migrations |
| HttpWebRequest | HttpClient + Polly | Async, retry policies, circuit breaker |
| SmtpClient (sync) | MailKit or async queue | Non-blocking, modern TLS |
| ConfigurationManager | IConfiguration + Azure Key Vault | Environment separation, no secrets in files |
| EventLog | ILogger + Serilog/Application Insights | Structured logging, cloud-compatible |

## What NOT to Do

- ❌ **Don't rewrite everything at once** — incremental phases reduce risk
- ❌ **Don't skip the testing phase** — refactoring without tests is how regressions happen
- ❌ **Don't ignore the SQL injection** — it's a live vulnerability regardless of modernization plans
- ❌ **Don't change the external API contract** — other systems may depend on order IDs and email format
