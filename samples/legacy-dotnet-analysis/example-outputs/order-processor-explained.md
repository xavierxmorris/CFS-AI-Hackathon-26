## What This Code Does

`OrderProcessor` is the **central orchestrator** of the order system. When a customer places an order, this single class handles *everything*: validating the customer, checking inventory, calculating prices and taxes, processing payment, saving the order to the database, and sending a confirmation email.

### Step-by-Step Flow (in plain English)

1. **Validate the customer** — Looks up the customer by ID using `CustomerRepository`. Rejects the order if the customer doesn't exist or isn't active.

2. **Check product availability** — Queries the `Products` table directly (inline SQL) to get the unit price and stock count. Rejects if the product doesn't exist or stock is insufficient.

3. **Calculate the total** — Multiplies unit price × quantity, adds state-specific sales tax using a hardcoded tax table (`CA: 7.25%`, `NY: 8%`, `TX: 6.25%`, default: `5%`).

4. **Apply loyalty discount** — If the customer has more than 500 loyalty points, applies a 10% discount capped at $50. This was added in 2018 as a separate code path.

5. **Process payment** — Delegates to `PaymentService.ChargeCustomer()`, passing the customer email, total amount, and payment token. If payment fails, the order is rejected.

6. **Create the order record** — Within a SQL transaction:
   - Inserts a row into the `Orders` table
   - Decrements the product's `StockCount`
   - Adds loyalty points to the customer (1 point per $10 spent)
   - If any step fails, the entire transaction is rolled back

7. **Send confirmation email** — Uses `System.Net.Mail.SmtpClient` with settings from `Web.config`. Email failures are logged but **do not** cancel the order.

### Return Value

- Returns the new **order ID** (positive integer) on success
- Returns **-1** on any failure

## What an Experienced Developer Should Know

- **This is a "God class"** — it owns business logic, data access, payment integration, email sending, and tax calculation. Any change to any of those concerns means changing this file.
- **The tax calculation is hardcoded** — the `GetTaxRate()` switch statement will need updating whenever tax rules change or new states are added.
- **Error handling returns -1** — callers have no way to distinguish between "customer not found" and "payment failed" without reading the event log.
- **The loyalty discount was bolted on** — it checks `LoyaltyPoints` inline but the feature flag in `Web.config` (`EnableLoyaltyDiscount`) is never actually read.
- **Logging goes to Windows Event Log** — this won't work in containers, Linux, or cloud environments.
